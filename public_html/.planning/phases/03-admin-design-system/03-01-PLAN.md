**Step A — Audit and categorize the 89 manual CSRF injection files:**

Run: `grep -rln "get_csrf_token_name\|get_csrf_hash" application/modules/ --include="*.php"`

For each file in the results, read it and determine the injection type:
- **Type 1 — Form hidden input** (safe to keep for traditional form POSTs):
  `<input type="hidden" name="..." value="<?php echo $CI->security->get_csrf_hash(); ?>">`
  These are harmless — CI3 accepts the prefilter-injected version and the form's hidden input both.
  LEAVE THESE UNCHANGED.

- **Type 2 — AJAX data object** (must remove to prevent double-token conflict after regeneration):
  `data: { csrf_token_name: csrf_hash, ... }` or
  `data: '<?php echo $CI->security->get_csrf_token_name(); ?>=<?php echo $CI->security->get_csrf_hash(); ?>&...'`
  in a `$.ajax()`, `$.post()`, `$.get()` call.
  REMOVE THE CSRF KEY from the data object. Leave all other data keys intact.

**Step B — For each Type 2 occurrence, apply the removal:**
Remove only the CSRF token key-value pair from the AJAX data object. Examples:

Before: `data: { name: name_val, <?php echo $CI->security->get_csrf_token_name(); ?>: '<?php echo $CI->security->get_csrf_hash(); ?>' }`
After: `data: { name: name_val }`

Before: `data: csrf_name + '=' + csrf_val + '&patient_id=' + id`
After: `data: 'patient_id=' + id`

Before (standalone CSRF-only data): `data: { <?php echo get_csrf_token_name(); ?>: '<?php echo get_csrf_hash(); ?>' }`
After: `data: {}`

Do NOT remove: `var csrf_token_name = '<?php echo $CI->security->get_csrf_token_name(); ?>';`
variable declarations that are used elsewhere in the file (only remove the actual AJAX data injection).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → CI3 controller (AJAX POST) | CSRF token validates that the POST originated from the same-origin admin session |
| ajaxSuccess handler → window.CI_CSRF_HASH | Frontend JS reads csrf_hash from JSON response; no server trust boundary crossed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Spoofing | CSRF token replay (fixed token per 2h session) | mitigate | `csrf_regenerate = true` invalidates token after each POST; replay window reduced to single-request lifetime |
| T-03-01-02 | Denial | Double-token conflict on sequential AJAX POST | mitigate | Patch csrf_inject.php before enabling regeneration; remove manual AJAX data injections from 89 view files |
| T-03-01-03 | Spoofing | window.CI_CSRF_HASH readable by any JS on page | accept | Admin-only pages behind Ion Auth session; same-origin; no cross-origin script can read this value |
</threat_model>
