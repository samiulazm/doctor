# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: Admin Design System.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This is a BROWNFIELD standardization phase. No new design system is being
> introduced. All tokens are drawn from the existing `app-design-tokens.css`
> CSS custom-property layer already loaded on every admin page via
> `application/assets/css/app-design-tokens.css`. The contract below codifies
> what already exists so that (a) non-conforming modules can be identified and
> (b) Phases 4–6 have an authoritative reference when building new portal pages.
>
> Primary visual anchor: the teal `btn-primary` CTA in the card header is the
> intended focal point on every list view page. The Outfit card title is the
> secondary anchor.

## Spacing Scale

All values map to existing `--ap-space-*` tokens declared in `app-design-tokens.css`.
All values are multiples of 4px.

| Token | CSS Variable | Value | Usage |
|-------|-------------|-------|-------|
| xs | `--ap-space-1` | 4px (0.25rem) | Icon gaps, dot separators, badge inner padding |
| sm | `--ap-space-2` | 8px (0.5rem) | Compact row padding, button icon gap |
| md | `--ap-space-4` | 16px (1rem) | Default form group spacing, table cell padding (horizontal) |
| lg | `--ap-space-6` | 24px (1.5rem) | Card header vertical padding, page header padding, card body padding, modal header/footer padding |
| 2xl | `--ap-space-8` | 32px (2rem) | Section gaps between cards, empty-state padding |
| 3xl | (no token) | 48px | Major page-level vertical breaks — use Bootstrap `py-4` (1.5rem × 2) or `py-5` |

Exceptions:
- Touch targets (action buttons in DataTable rows): minimum 36px height enforced by `.ap-icon-btn` (height: 2.25rem)
- Table cell padding: 0.85rem vertical × 0.9rem horizontal (defined directly in `app-design-tokens.css` `.content-wrapper .table tbody td`); retained from existing AdminLTE 3 vendor defaults — rounding to 12px/16px would alter table row density across 70+ existing module views, introducing unacceptable regression risk.

## Typography

Source: `app-design-tokens.css` + `home/views/dashboard.php` Google Fonts import.
Declare exactly 4 roles; use exactly 2 weights for body content.

| Role | CSS Variable / Class | Size | Weight | Line Height | Font |
|------|---------------------|------|--------|-------------|------|
| Body | `--ap-font-body` | 14px (0.875rem) | 400 (regular) | 1.5 | DM Sans |
| Label | `.content-wrapper label` | 13px (0.8125rem) | 700 (bold) | 1.4 | DM Sans |
| Table header | `.content-wrapper .table thead th` | 12px (0.75rem) | 700 (bold) | 1.3 | DM Sans, uppercase, 0.035em letter-spacing |
| Card title / Page heading | `.content-wrapper .card-title`, `h1` in `.content-header` | clamp(21.6px, 1.1vw + 16px, 30px) | 700 (bold) | 1.18 | Outfit |

Weight palette: 400 (body text, table cell values) and 700 (labels, headings, table headers). No other weights are permitted on admin pages.

## Component Contracts

These are the precise HTML/class patterns that constitute "conforming" for Phase 3.
Executor must match these exactly; deviating modules are non-conforming.

### Card / Section Layout (UI-01)

Every module list view must use this structure. No legacy inline-styled sections.

```html
<div class="content-wrapper bg-light">
    <?php $CI->load->view('partials/page_header', [
        'title'       => lang('module_name'),
        'icon'        => 'fas fa-icon-name text-primary mr-2',
        'breadcrumbs' => [
            ['label' => lang('home'),        'url' => 'home'],
            ['label' => lang('module_name'), 'url' => null],
        ],
    ]); ?>

    <section class="content py-4">
        <div class="container-fluid">
            <div class="row justify-content-center">
                <div class="col-12">
                    <div class="card shadow-sm border-0">
                        <div class="card-header bg-white border-bottom d-flex flex-wrap align-items-center justify-content-between gap-2 py-3">
                            <h3 class="card-title h6 mb-0 text-muted text-uppercase">
                                <?php echo lang('list_label'); ?>
                            </h3>
                            <!-- Primary action button (if applicable) -->
                            <button type="button" class="btn btn-sm btn-primary"
                                    data-toggle="modal" data-target="#addModal">
                                <i class="fas fa-plus mr-1"></i>
                                <?php echo lang('add_new'); ?>
                            </button>
                        </div>
                        <div class="card-body p-4">
                            <div class="custom_buttons mb-3"></div>
                            <div class="table-responsive">
                                <table class="table table-hover table-bordered align-middle mb-0"
                                       id="dt-MODULE_NAME" style="width:100%">
                                    <!-- thead and empty tbody — DataTables populates -->
                                </table>
                            </div>
                        </div>
                    </div>
                </div>
            </div>
        </div>
    </section>
</div>
```

Non-conforming patterns to replace:
- `<section class="content-header py-4 bg-white shadow-sm">` with inline `<h1 class="display-4">` — replace with `partials/page_header` partial
- `<div class="content-wrapper bg-gradient-light">` without the card wrapper — add card
- Any `<div style="...">` layout sections — strip inline styles, apply token classes

### DataTables Config (UI-02)

Every list view table must be initialized with this server-side config. Replace any
`editable-table.js` (`EditableTable.init()`) initializations with this pattern.

```javascript
// Standard server-side DataTable initialization
// Table ID convention: dt-{module_name} (e.g. dt-doctor, dt-patient, dt-lab)
$('#dt-MODULE_NAME').DataTable({
    processing: true,
    serverSide: true,
    ajax: {
        url: BASE_URL + 'module/datatableData',
        type: 'POST'
        // CSRF token is injected automatically by csrf_inject.php $.ajaxPrefilter
    },
    columns: [
        // column definitions specific to module
        { data: 'id',      title: LANG.id },
        { data: 'name',    title: LANG.name },
        // ...
        { data: 'actions', title: LANG.actions, orderable: false, searchable: false }
    ],
    order: [[0, 'desc']],
    pageLength: 25,
    lengthMenu: [[10, 25, 50, 100], [10, 25, 50, 100]],
    responsive: true,
    dom: '<"row mb-3"<"col-sm-6"l><"col-sm-6 text-right"f>>' +
         '<"row"<"col-12"tr>>' +
         '<"row mt-3"<"col-sm-5"i><"col-sm-7"p>>',
    buttons: ['copy', 'csv', 'excel', 'pdf', 'print', 'colvis'],
    language: {
        search: '',
        searchPlaceholder: 'Search...',
        processing: '<i class="fas fa-spinner fa-spin"></i> Loading...'
    }
});
```

Server-side controller method must accept and respond to DataTables parameters:
`draw`, `start`, `length`, `search[value]`, `order[0][column]`, `order[0][dir]`.
Use the four-method model pattern already established:
`getByLimit()`, `getByLimitBySearch()`, `getWithoutSearch()`, `getBySearch()`.

### CSRF Contract (UI-03)

The global `csrf_inject.php` view (loaded in `home/views/footer.php` line 134) already
injects a `$.ajaxPrefilter` that appends the CSRF token to every POST request.

**The two remaining gaps that Phase 3 must close:**

1. `csrf_regenerate` in `application/config/config.php` must be set to `true`:
   ```php
   $config['csrf_regenerate'] = true;
   ```
   Current value: `false` (line 481 of config.php).

2. Any view that constructs its own inline AJAX `data: { ... }` object without relying
   on the prefilter must be audited. The prefilter handles plain objects, FormData, and
   query strings — manual token injection in view code is redundant and should be removed
   to avoid double-token conflicts after `csrf_regenerate = true` is enabled.

When `csrf_regenerate = true` is active, each POST response returns a new hash.
The prefilter only captures the hash at page-load time. Modules that make multiple
sequential AJAX POSTs on a single page load must refresh the hash from the response
header `X-CSRF-Token` or a JSON `csrf_hash` field in the response envelope.

**Standard AJAX response envelope** (all AJAX endpoints must return this shape):
```json
{
    "success": true,
    "message": "Record saved.",
    "data": { ... },
    "csrf_hash": "new_hash_here"
}
```
The front-end must update the in-memory hash after each POST:
```javascript
// In $.ajaxSetup or a global success handler
$(document).ajaxSuccess(function(event, xhr, settings, data) {
    if (data && data.csrf_hash) {
        // csrf_inject.php exposes h as a module-scoped variable — cannot patch directly.
        // Use a global window.CI_CSRF_HASH updated by the prefilter.
        window.CI_CSRF_HASH = data.csrf_hash;
    }
});
```
The csrf_inject.php prefilter should read from `window.CI_CSRF_HASH` (falling back to
the page-load hash) so sequential POSTs always use the latest token.

### Button Variants (UI-04)

Three button classes are permitted. No custom inline styles on buttons.

| Variant | Class | When to use |
|---------|-------|------------|
| Primary | `btn btn-sm btn-primary` | Single primary action per card header (Add New, Save Changes) |
| Secondary | `btn btn-sm btn-secondary` / `btn btn-sm btn-outline-secondary` | Cancel, Close, secondary actions in modal footers |
| Danger | `btn btn-sm btn-danger` | Delete/remove — must always show a confirmation dialog before executing |

Button sizing: `btn-sm` everywhere in admin list views (height ≥ 36px enforced by
`.content-wrapper .btn` min-height: 2.375rem rule). Full-size `btn` is permitted only
inside modal footers for primary submit actions.

Row action buttons use `.ap-icon-btn` (36px square icon button, no text label):
```html
<div class="ap-row-actions">
    <a href="#" class="ap-icon-btn" title="Edit"><i class="fas fa-edit"></i></a>
    <a href="#" class="ap-icon-btn text-danger" title="Delete"
       onclick="return confirmDelete(id)"><i class="fas fa-trash"></i></a>
</div>
```

### Modal Template (UI-04)

Standard Bootstrap modal structure. All modals must use this template.

```html
<div class="modal fade" id="addModal" role="dialog"
     aria-labelledby="addModalLabel" aria-hidden="true" tabindex="-1">
    <div class="modal-dialog modal-lg modal-dialog-scrollable" role="document">
        <div class="modal-content">
            <div class="modal-header">
                <h5 class="modal-title" id="addModalLabel">
                    <i class="fas fa-plus mr-2"></i>
                    <?php echo lang('add_new'); ?>
                </h5>
                <button type="button" class="close" data-dismiss="modal"
                        aria-label="<?php echo lang('close'); ?>">
                    <span aria-hidden="true">&times;</span>
                </button>
            </div>
            <div class="modal-body">
                <form id="addForm" method="post" action="module/addNew">
                    <!-- CSRF: injected automatically by csrf_inject.php -->
                    <!-- form fields -->
                </form>
            </div>
            <div class="modal-footer border-top bg-light">
                <button type="button" class="btn btn-secondary"
                        data-dismiss="modal"><?php echo lang('close'); ?></button>
                <button type="button" class="btn btn-primary px-4"
                        id="addModalSubmit"><?php echo lang('save_changes'); ?></button>
            </div>
        </div>
    </div>
</div>
```

Modal sizes: `modal-lg` for add/edit forms; `modal-xl` for detail views; `modal-sm`
for simple confirmations.

### Input Fields (UI-04)

All form inputs inside admin views must use Bootstrap 4 form classes with
no inline `style` overrides. The token layer in `app-design-tokens.css` applies
border, border-radius, min-height, and focus ring globally.

```html
<div class="form-group">
    <label for="field_id"><?php echo lang('field_label'); ?> <span class="text-danger">*</span></label>
    <input type="text" class="form-control" id="field_id" name="field_name"
           placeholder="" required>
</div>

<!-- Select with Select2 -->
<div class="form-group">
    <label for="select_id"><?php echo lang('field_label'); ?></label>
    <select class="form-control w-100" id="select_id" name="field_name">
        <option value=""></option>
    </select>
</div>
```

`form-control-lg` is permitted only when the field is the primary focus element in a
modal (e.g. patient name in appointment add modal). Standard forms use `form-control`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (list view) | "Add New [Module Name]" — e.g. "Add New Doctor", "Add New Patient" |
| Primary CTA (modal footer) | "Save Changes" (not "Save", not "Submit", not "OK") |
| Empty state heading | "No [records] found" — e.g. "No appointments found" |
| Empty state body | "No [module name] records exist yet. Click 'Add New [Module Name]' to create the first one." |
| DataTables no-results | "No matching records found" (DataTables default — do not override) |
| DataTables loading | `<i class="fas fa-spinner fa-spin"></i> Loading...` |
| Error state (AJAX failure) | "Unable to load data. Please refresh the page or contact support if the problem persists." |
| Error state (form validation) | "[Field name] is required." — one message per field, inline below the input using Bootstrap `.invalid-feedback` |
| Delete confirmation | "Delete [Record Name]? This action cannot be undone." — use `confirm()` dialog or SweetAlert2 `Swal.fire({ icon: 'warning', showCancelButton: true })` |
| CSRF error (419 equivalent) | "Your session has expired. Please refresh the page and try again." |

Destructive actions in Phase 3:
- Delete button in every module list view → confirmation required before DELETE/POST
- Confirmation approach: SweetAlert2 `Swal.fire()` with `icon: 'warning'`, `confirmButtonText: 'Yes, delete it'`, `cancelButtonText: 'Cancel'`
- No delete executes without a confirmed SweetAlert2 dialog

Language key pattern: all user-visible strings must use `lang('key')` helper, not
hardcoded English strings, to preserve i18n compatibility.

## Conformance Checklist

For each admin module view, the following must be TRUE before Phase 3 is complete:

### Layout (UI-01)
- [ ] `<div class="content-wrapper bg-light">` wraps the page
- [ ] `partials/page_header` partial is used (not inline `content-header` HTML)
- [ ] Content is inside `<section class="content py-4">` > `.container-fluid`
- [ ] Primary list card uses `.card.shadow-sm.border-0` with `.card-header` + `.card-body.p-4`
- [ ] No `<div style="...">` layout sections exist in the view
- [ ] No `<table>` without `class="table table-hover table-bordered align-middle mb-0"`

### DataTables (UI-02)
- [ ] Table has `id="dt-{module_name}"` and `style="width:100%"`
- [ ] Table is initialized via `$('#dt-...').DataTable({ serverSide: true, ... })`
- [ ] `EditableTable.init()` call is absent (legacy pattern removed)
- [ ] Table has `<thead>` with column labels via `lang()` and empty `<tbody>`
- [ ] Actions column has `orderable: false, searchable: false`
- [ ] Server controller method returns DataTables-compatible JSON with `draw`, `recordsTotal`, `recordsFiltered`, `data` keys

### CSRF (UI-03)
- [ ] `csrf_regenerate = true` in `application/config/config.php`
- [ ] No view manually constructs CSRF token in inline `$.ajax({ data: { csrf_token: ... } })` — relies on `csrf_inject.php` prefilter instead
- [ ] AJAX endpoints return `csrf_hash` in response JSON envelope
- [ ] Front-end updates `window.CI_CSRF_HASH` from response to support multi-POST flows

### Design Tokens (UI-04)
- [ ] Buttons use only `btn-primary`, `btn-secondary`/`btn-outline-secondary`, `btn-danger`
- [ ] No `style="background-color:..."` or `style="color:..."` on buttons
- [ ] Status values rendered via `.ap-status` + `.ap-status-{success|warning|danger|info}` classes
- [ ] No raw Bootstrap `badge-success`, `badge-warning`, `badge-danger` without `.ap-status` wrapper
- [ ] Delete actions use SweetAlert2 confirmation before executing
- [ ] Modal structure matches the standard template (modal-header + modal-body + modal-footer)
- [ ] Form labels use `.form-group` > `label` + `.form-control` pattern
