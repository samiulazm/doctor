# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4: Patient Portal.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This is a BROWNFIELD EXTENSION phase. The portal module (`application/modules/portal/`)
> and its companion stylesheet (`common/css/chamber-practice.css`) already exist.
> This contract codifies the complete visual and interaction surface required to satisfy
> UI-05, UI-06, UI-07, UI-08, AUTH-01, and PAY-02 — including the screens that are
> currently missing (patient home, dedicated queue screen, prescription view).
>
> The patient portal is MOBILE-FIRST. Bangladesh market — majority mobile users.
> Every layout collapses to a single-column stacked card at 575px and below.
> No admin UI (AdminLTE 3, DataTables, card-header/card-body pattern) is used here.
> The portal lives at `application/modules/portal/` and its views use
> `portal/layout_public` as the outer shell, NOT `home/dashboard`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Bootstrap 4.6 via CDN + custom `.chamber-*` component layer) |
| Preset | not applicable |

**No new CSS files are to be created.** All new portal styles are added to `chamber-practice.css`.
`--chamber-*` variables are the authoritative token names for portal views.

## Spacing Scale

Token names map to `--ap-space-*` values declared in `app-design-tokens.css`.
All values are multiples of 4px.

| Token | CSS Variable | Value | Usage |
|-------|-------------|-------|-------|
| xs | `--ap-space-1` | 4px | Icon gap inside pills, dot separator, badge inner |
| sm | `--ap-space-2` | 8px | Gap between stacked pills, button icon gap, radio-pill gap |
| md | `--ap-space-4` | 16px | Panel padding (`.chamber-public-panel` uses 18px — retain), form group margin, section inner padding |
| lg | `--ap-space-6` | 24px | Vertical rhythm between panels, hero content top padding on mobile |
| xl | `--ap-space-8` | 32px | Top/bottom section breaks on full-width hero |
| 2xl | (no token) | 48px | Major page-level vertical breaks — use Bootstrap `py-4` or `py-5` class |

Exceptions:
- `.chamber-public-panel` uses `padding: 18px` (existing — do not change; value is between md/lg and intentional for the card feel)
- Touch targets: all interactive elements must have `min-height: 44px` on mobile. The `.btn` in portal context must be full-width on `max-width: 575px` (already handled by `chamber-practice.css` `.chamber-btn-row .btn` rule — extend to primary CTAs in all portal views)
- Queue serial number display (UI-07): the serial number itself uses `font-size: 80px` at `font-weight: 800` — this is a single glance-able number, not a typography scale violation
- Hero image (`chamber-public-hero`): `min-height: 420px` desktop, `min-height: 360px` tablet, `min-height: 240px` mobile — existing values, retain

## Typography

Source: `app-design-tokens.css` Google Fonts import + `chamber-practice.css` component rules.
Declare exactly 4 roles; use exactly 2 weights for body content.

| Role | CSS Variable / Class | Size | Weight | Line Height | Font |
|------|---------------------|------|--------|-------------|------|
| Body / Form labels | `--chamber-text`, `.chamber-muted` | 15px (0.9375rem) | 400 (regular) | 1.5 | DM Sans |
| Label / Kicker / Status | `.chamber-kicker`, `.chamber-status` | 12px (0.75rem) | 700 (bold) | 1.3 | DM Sans, uppercase, 0.06em letter-spacing |
| Panel title / Section heading | `.chamber-panel-title` | 16px (1rem) | 700 (bold) | 1.25 | DM Sans |
| Hero display heading | `.chamber-public-hero h1` | clamp(34px, 5vw, 58px) | 800 (extrabold) | 1 | Outfit |

Weight palette for body content: 400 (body text, muted descriptions) and 700 (labels, panel titles, status badges, kickers).
Weight 800 is permitted ONLY for: hero `h1`, queue serial number display (`.queue-serial-number`), stat values (`.chamber-stat-value`).
No other weights are used in portal views.

### OTP Modal Contract (AUTH-01)

The OTP flow is implemented inline in `triage.php` (not a Bootstrap modal). This approach is retained.
The pattern must satisfy these interaction rules:

1. Mobile number field: `<input type="tel" inputmode="numeric" pattern="[0-9+\-\s]+" autocomplete="tel">` — triggers numeric keyboard on iOS/Android
2. "Send OTP" button: disabled during AJAX in-flight (add `disabled` attribute, restore on complete)
3. OTP field: only appears after successful `request_otp` response (`r.ok === true`)
4. OTP input: `inputmode="numeric"` to trigger numeric keyboard; `autocomplete="one-time-code"` for SMS autofill on Android
5. "Verify OTP" button: disabled during AJAX in-flight
6. Success state: show `.chamber-status.arrived` inline badge with text "Verified" next to mobile number
7. Rate-limit message (from server `r.ok === false, r.msg = "Too many OTP requests..."`): shown in `#otpMsg` as `.text-danger` (not `.text-muted`)

## Interaction Contracts

### CSRF

Portal forms use inline CSRF token injection (already present in `triage.php`):
```php
<input type="hidden"
    name="<?php echo $this->security->get_csrf_token_name(); ?>"
    value="<?php echo $this->security->get_csrf_hash(); ?>">
```
AJAX calls in portal views do NOT use the global `csrf_inject.php` prefilter (that is admin-only).
Portal AJAX must include the token manually in each POST data object. This is correct for the
portal context — retain this pattern.

### Loading States

All AJAX-triggered buttons must show a loading state while the request is in-flight:
```javascript
// Pattern for all portal AJAX buttons
$('#btnOtp').on('click', function () {
    var $btn = $(this);
    $btn.prop('disabled', true).html('<i class="fas fa-spinner fa-spin mr-1"></i> Sending...');
    $.post(url, data, function (r) {
        // restore on complete
    }).always(function () {
        $btn.prop('disabled', false).html('Send OTP');
    });
});
```

### Mobile Keyboard Optimization

| Input | `type` | `inputmode` | `autocomplete` |
|-------|--------|-------------|----------------|
| Mobile number | `tel` | `numeric` | `tel` |
| OTP code | `text` | `numeric` | `one-time-code` |
| Age | `number` | `numeric` | `off` |
| Date | `date` | (not set) | `off` |
| Full name | `text` | `text` | `name` |

### Live Queue Polling

Queue screen and landing page ticker use `setInterval(fn, 15000)` — poll every 15 seconds.
On visibility change (`document.addEventListener('visibilitychange')`), pause polling when tab is hidden and resume when visible. This reduces unnecessary requests on mobile with the screen off.

```javascript
var tickerInterval = null;
function startTicker() { tickerInterval = setInterval(loadTicker, 15000); }
function stopTicker() { clearInterval(tickerInterval); }
document.addEventListener('visibilitychange', function () {
    document.hidden ? stopTicker() : startTicker();
});
startTicker();
```
