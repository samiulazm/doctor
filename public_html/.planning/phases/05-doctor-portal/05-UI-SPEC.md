# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5: Doctor Portal.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This is a BROWNFIELD extension phase. The `doctor_chamber` module already has a
> working skeleton (`dashboard.php`, `consultation_room.php`) with a dedicated CSS
> layer (`common/css/chamber-practice.css`). Phase 5 extends that skeleton into the
> full UI-09, UI-10, UI-11 contract. No new design system is being introduced.
>
> All tokens in this phase are `.chamber-*` CSS custom properties, which themselves
> delegate to the Phase 3 `--ap-*` token layer in `app-design-tokens.css`.
> The two layers must remain in sync — do not introduce independent hex values.
>
> Screens in scope:
> 1. Doctor Dashboard (UI-09 + UI-10) — `doctor_chamber/dashboard`
> 2. Consultation Room (UI-11) — `doctor_chamber/consultation_room`

## Spacing Scale

All values inherited from Phase 3 `--ap-space-*` tokens, aliased as `--chamber-*` in `chamber-practice.css`.
All values are multiples of 4px.

| Token | CSS Variable | Value | Usage |
|-------|-------------|-------|-------|
| xs | `--ap-space-1` | 4px | Icon gaps, dot separators, stat icon margin |
| sm | `--ap-space-2` | 8px | `.chamber-actions` gap, button icon gap, vitals grid gap |
| md | `--ap-space-4` | 16px | `.chamber-panel-body` padding, `.chamber-stat` padding, toolbar gap |
| lg | `--ap-space-6` | 24px | Page section vertical breaks, card header padding |
| xl | `--ap-space-8` | 32px | Dashboard section gaps (between stat grid and queue panel) |

Existing chamber-specific spacings (updated to 4px grid):
- `.chamber-stat-grid` gap: 12px — updated from 14px to nearest 4px multiple (12 = 3×4)
- `.chamber-panel-header` padding: 12px 16px — updated from 14px vertical to 12px
- `.chamber-panel` margin-bottom: 16px — updated from 18px to nearest 4px multiple (16 = 4×4)

Exceptions:
- Stat card icon container: 36x36px (`height: 36px; width: 36px`) — touch target floor for action affordance
- Consultation room split: left 40%, right 60% (Bootstrap `col-md-5` / `col-md-7` approximation) — see Component Contracts

## Typography

Source: `app-design-tokens.css` + `home/views/dashboard.php` Google Fonts import (inherited from Phase 3).
Exactly 4 roles; exactly 2 weights for body content.

| Role | CSS Variable / Class | Size | Weight | Line Height | Font |
|------|---------------------|------|--------|-------------|------|
| Body / table cell | `--ap-font-body` | 14px (0.875rem) | 400 (regular) | 1.5 | DM Sans |
| Label / kicker / muted text | `.chamber-kicker`, `.chamber-stat-label`, `.chamber-vital-label` | 12–13px (0.75–0.8125rem) | 700 (bold) | 1.4 | DM Sans |
| Panel title / section heading | `.chamber-panel-title`, `.chamber-head h1` | 16px (1rem) | 700 (bold) | 1.25 | DM Sans |
| Stat value / prominent number | `.chamber-stat-value`, `.chamber-vital-value` | 28px (1.75rem) — vital value uses 16px/panel-title step | 700 (bold) | 1 | Outfit |

Weight palette: 400 (body, table cells, descriptions) and 700 (labels, headings, status pills, stat/vital numerals). No other weights permitted.
Outfit at 700 provides sufficient differentiation from DM Sans at 700 via letterform geometry — weight 800 is not needed.

## Color

Source: `--chamber-*` properties in `chamber-practice.css` (`:root` block, lines 2–16), which delegate to `--ap-*`.

| Role | CSS Variable | Hex Value | Usage |
|------|-------------|-----------|-------|
| Dominant (60%) | `--chamber-bg` → `--ap-page-bg` | `#f6f8fb` | `.chamber-ui` background, page background |
| Secondary (30%) | `--chamber-surface` / `--chamber-surface-soft` → `--ap-surface` | `#ffffff` / `#f8fafc` | `.chamber-panel`, `.chamber-stat`, `.chamber-toolbar`, table header rows |
| Accent (10%) | `--chamber-primary` → `--ap-primary-strong` | `#0f766e` (teal-700) | See reserved-for list below |
| Alert blue | `--chamber-blue` → `--ap-blue` | `#2563eb` | AI strip border/icon color, `.chamber-status.done/.paid` text |
| Destructive | `--chamber-red` → `--ap-danger` | `#dc2626` | `.chamber-status.cancelled/.failed/.high_risk`, delete confirmations |

**Accent (`#0f766e`) is reserved for:**
- `.chamber-stat-icon` background tint (`rgba(15,118,110,0.12)`) and icon color
- `.chamber-kicker` text color (section eyebrow label "Doctor portal")
- Form control focus border (`border-color: var(--chamber-primary)`) with 3px teal focus ring
- `.chamber-radio-pill input:checked + span` selected state
- `.btn-primary` and `.btn-outline-primary` in chamber action bar (inherits from Phase 3 `--ap-primary` → Bootstrap override)
- `.chamber-status.arrived/.serving` text color (`#047857` — uses `--chamber-green`, a subordinate accent)

**Status tag semantic mapping** (from `.chamber-status.*` — doctor portal equivalent of Phase 3 `.ap-status-*`):

| Status | Class | Background | Text | Use |

| Done / Paid | `.chamber-status.done`, `.chamber-status.paid` | `#eff6ff` | `#1d4ed8` | Consultation complete |

#### Patient Search Toolbar

Two search modes: by date (shows all patients seen on that date) OR by unique patient ID.
Search mode is toggled by radio pills, not two separate forms.

```html
    <section class="content">
        <!-- Patient search toolbar -->
        <div class="chamber-toolbar">
            <div class="chamber-radio-group mr-3">
                <label class="chamber-radio-pill">
                    <input type="radio" name="searchMode" value="id" checked>
                    <span>By patient ID</span>
                </label>
                <label class="chamber-radio-pill">
                    <input type="radio" name="searchMode" value="date">
                    <span>By date</span>
                </label>
            </div>
            <input type="number" id="searchPatientId" class="form-control mr-2"
                   placeholder="Patient ID" style="max-width:160px;"
                   value="<?php echo $patient ? (int) $patient->id : ''; ?>">
            <input type="date" id="searchDate" class="form-control mr-2"
                   style="max-width:180px; display:none;"
                   value="<?php echo date('Y-m-d'); ?>">
            <button class="btn btn-primary" id="btnSearchPatient" type="button">
                <i class="fas fa-search mr-1"></i> Load patient
            </button>
        </div>
```

Search mode interaction:
- Default: "By patient ID" radio selected → `#searchPatientId` visible, `#searchDate` hidden
- When "By date" selected: `#searchDate` visible, `#searchPatientId` hidden
- "Load patient" button triggers AJAX GET to `doctor_chamber/search_json` with params `{ mode, id|date }`
- Response populates `#searchResultsList` in LEFT panel — see below

## Interaction Contracts

### Live Queue Long-Poll (UI-10)

Same pattern as patient portal queue — shared hosting cannot sustain WebSocket connections.

```javascript
// Dashboard: live queue poll
(function () {
    var POLL_INTERVAL = 12000; // 12 seconds
    function pollQueue() {
        $.getJSON(BASE_URL + 'doctor_chamber/queue_json', function (r) {
            if (!r || !r.rows) return;
            var tbody = document.getElementById('liveQueueBody');
            var html = '';
            if (r.rows.length === 0) {
                html = '<tr><td colspan="6" class="text-muted text-center py-4">No active queue yet today.</td></tr>';
            } else {
                r.rows.forEach(function (q) {
                    var statusClass = q.status || 'pending';
                    html += '<tr>' +
                        '<td>' + parseInt(q.serial_number, 10) + '</td>' +
                        '<td>' + escHtml(q.guest_name || ('#' + q.patient_id)) + '</td>' +
                        '<td>' + escHtml(q.chamber_name || '') + '</td>' +
                        '<td><span class="chamber-status ' + escHtml(statusClass) + '">' + escHtml(statusClass) + '</span></td>' +
                        '<td>' + escHtml(q.triage_summary || '') + '</td>' +
                        '<td>' + (q.patient_id
                            ? '<a class="btn btn-xs btn-primary" href="' + BASE_URL + 'doctor_chamber/consultation_room?patient=' + parseInt(q.patient_id, 10) + '"><i class="fas fa-door-open"></i> Open</a>'
                            : '') + '</td>' +
                        '</tr>';
                });
            }
            tbody.innerHTML = html;
            var el = document.getElementById('queueLastUpdated');
            if (el) el.textContent = 'Updated ' + new Date().toLocaleTimeString('en-BD', { hour: '2-digit', minute: '2-digit' });
        });
    }
    pollQueue();
    setInterval(pollQueue, POLL_INTERVAL);
    function escHtml(s) {
        return String(s).replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;').replace(/"/g,'&quot;');
    }
}());
```

JSON endpoint contract (`doctor_chamber/queue_json`):

```json
            "patient_id": 42,
            "guest_name": "Rahim Ahmed",
            "chamber_name": "Chamber A",
            "status": "serving",
            "triage_summary": "Chest pain (2 days)"
        }
    ]
}
```

### Medicine Search Autocomplete (UI-11)

Debounced keyup on `#drugq`, minimum 2 characters, calls `doctor_chamber/drug_search_json?term={q}`.

```javascript
var drugTimer = null;
$('#drugq').on('keyup', function () {
    var t = $(this).val().trim();
    clearTimeout(drugTimer);
    if (t.length < 2) { $('#drugout').empty(); return; }
    drugTimer = setTimeout(function () {
        $.getJSON(BASE_URL + 'doctor_chamber/drug_search_json', { term: t }, function (rows) {
            var h = '';
            (rows || []).forEach(function (x) {
                h += '<li><button type="button" class="btn btn-link btn-sm p-0 text-left drug-pick">' +
                    $('<div>').text(x.label || '').html() + '</button></li>';
            });
            $('#drugout').html(h);
        });
    }, 280); // 280ms debounce
});
$(document).on('click', '.drug-pick', function () {
    var name = $(this).text().trim();
    var ta = $('#rxScratch');
    ta.val((ta.val() ? ta.val() + '\n' : '') + name);
    $('#drugout').empty();
    $('#drugq').val('');
});
```
