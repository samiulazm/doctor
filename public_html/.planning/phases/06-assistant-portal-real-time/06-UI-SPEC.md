# Phase 6 — UI Design Contract

> Visual and interaction contract for Phase 6: Assistant Portal + Real-Time.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This is a BROWNFIELD extension phase. The `assistant_chamber` module already has a
> working skeleton (`desk.php`, `manual_booking.php`, `bulk_sms.php`) with the
> `chamber-practice.css` token layer from Phase 5. Phase 6 refines that skeleton into
> the full UI-12, UI-13, PAY-01, and QUEUE-01 contract.
>
> All tokens in this phase are `.chamber-*` CSS custom properties from
> `common/css/chamber-practice.css`, which delegate to the Phase 3 `--ap-*` layer in
> `application/assets/css/app-design-tokens.css`. Two new CSS classes are introduced:
> `.chamber-status.emergency` and `.chamber-source-tag.*` — both added to
> `chamber-practice.css`.
>
> Screens in scope:
> 1. Assistant Queue Desk (UI-12) — `assistant_chamber/desk`
> 2. Billing Panel (UI-13 + PAY-01) — inline expand on queue row (dedicated billing
>    section within `desk.php`; no separate route needed)
> 3. Real-time queue ticker (QUEUE-01) — long-poll across doctor, assistant, and patient
>    views; wired via `assistant_chamber/desk` for the assistant side

## Spacing Scale

All values inherited from Phase 3 `--ap-space-*` tokens, aliased as `--chamber-*` in
`chamber-practice.css`. All values are multiples of 4px.

| Token | CSS Variable | Value | Usage |
|-------|-------------|-------|-------|
| xs | `--ap-space-1` | 4px | Icon gaps, source-tag inner padding, badge separator |
| sm | `--ap-space-2` | 8px | `.chamber-btn-row` gap, button icon gap, form-control-sm margin |
| md | `--ap-space-4` | 16px | `.chamber-panel-body` padding, billing form field spacing, toolbar gap |
| lg | `--ap-space-6` | 24px | Page section vertical breaks, card header padding |
| xl | `--ap-space-8` | 32px | Section gaps (between toolbar and queue panel) |

Exceptions:
- Drag handle cell (`.handle` column): 28px wide, `cursor: move` — not a touch target for actions, no minimum height enforcement needed
- Queue row action buttons: `btn-xs` class — height enforced at 28px (existing `chamber-practice.css` rule `.chamber-ui .btn-xs { padding: 3px 8px; font-size: 12px; }`)
- Vitals collapse form: `form-control-sm` — 28px height is acceptable for supplementary data entry not primary actions
- bKash status inline region: minimum 40px height to be readable on mobile

## Typography

Source: `app-design-tokens.css` + `home/views/dashboard.php` Google Fonts import
(inherited from Phases 3 and 5). Exactly 4 roles; exactly 2 weights for body content.

| Role | CSS Variable / Class | Size | Weight | Line Height | Font |
|------|---------------------|------|--------|-------------|------|
| Body / table cell | `--ap-font-body` | 14px (0.875rem) | 400 (regular) | 1.5 | DM Sans |
| Label / kicker / muted text | `.chamber-kicker`, `.chamber-stat-label`, `.chamber-source-tag` | 12–13px (0.75–0.8125rem) | 700 (bold) | 1.4 | DM Sans |
| Panel title / section heading | `.chamber-panel-title`, `.chamber-head h1` | 16px (1rem) | 700 (bold) | 1.25 | DM Sans |
| Billing amount / serial number | `.chamber-stat-value` (reused) | 28px (1.75rem) | 700 (bold) | 1 | Outfit |

Weight palette: 400 (body, table cells, descriptions, fee input value) and 700 (labels,
headings, status pills, serial numbers). No other weights permitted.

### Screen 3: Real-Time Queue Sync (QUEUE-01)

**Mechanism:** Long-poll at 12-second intervals (shared hosting — no WebSocket).
**Endpoints:**
- `assistant_chamber/queue_ticker_json` — returns `{ serial: N, serving_name: "...", updated_at: "..." }`
  This endpoint is shared with `doctor_chamber/queue_json` and `portal/queue_ticker_json`.
- `assistant_chamber/queue_reorder` — AJAX POST after drag-drop; triggers immediate ticker update

**Drag-drop reorder → broadcast contract:**

```javascript
// SortableJS initialization — already present in desk.php; PHASE 6 refinement below
(function () {
    var el = document.getElementById('queueBody');
    if (!el || !window.Sortable) return;

    Sortable.create(el, {
        handle: '.handle',
        animation: 150,
        onEnd: function () {
            // Collect new order and POST immediately (do not wait for "Save order" click)
            var ids = [];
            document.querySelectorAll('#queueBody tr[data-id]').forEach(function (tr) {
                ids.push(tr.dataset.id);
            });
            $.post(BASE_URL + 'assistant_chamber/queue_reorder', { order: ids }, function (r) {
                if (r && r.ok) {
                    toastr.success('Queue reordered.', '', { timeOut: 1500 });
                } else {
                    toastr.warning('Reorder saved locally — server sync failed.');
                }
            }, 'json').fail(function () {
                toastr.warning('Reorder saved locally — server sync failed.');
            });
        }
    });

    // "Save order" button retained as explicit fallback
    $('#saveOrder').on('click', function () {
        var ids = [];
        document.querySelectorAll('#queueBody tr[data-id]').forEach(function (tr) {
            ids.push(tr.dataset.id);
        });
        $.post(BASE_URL + 'assistant_chamber/queue_reorder', { order: ids }, function (r) {
            if (r && r.ok) {
                toastr.success('Order saved.');
            }
        }, 'json');
    });
}());
```

**PHASE 6 change from existing `desk.php`:** Reorder now fires `$.post` on `onEnd`
(immediately after drop) rather than only on "Save order" button click. This ensures
the doctor and patient queue ticker updates in real-time without the assistant manually
clicking save.

## Interaction Contracts

### Drag-and-Drop Reorder (UI-12)

- Library: SortableJS 1.15.0 from CDN (already in `desk.php`)
- Handle selector: `.handle` cell (first column, grip icon)
- Animation: 150ms (SortableJS `animation` option)
- On drop (`onEnd`): AJAX POST to `assistant_chamber/queue_reorder` with `order[]` array
- Success: Toastr success "Queue reordered." (1500ms, no manual dismiss needed)
- Failure: Toastr warning "Reorder saved locally — server sync failed."
- The "Save order" button (`#saveOrder`) is retained as an explicit fallback

### Check-In (UI-12)

- Trigger: "Check in" button (only shown when `status === 'pending'`)
- Method: Standard form POST to `assistant_chamber/checkin`
- CSRF: PHP `csrf_field()` helper output in form (generated by CI3 security library)
- Result: Page redirect back to `assistant_chamber/desk` with updated status tag

### Emergency Bump (UI-12)

- Trigger: "Emergency" button (danger red, shown for any non-done/cancelled row)
- Method: Form POST to `assistant_chamber/emergency_bump`
- Result: Row moves to top of `queueBody`, `is_emergency` flag set, status tag switches
  to `.chamber-status.emergency` on next page load
- Toastr: none (redirect refresh shows updated state)

### Print Serial Token (UI-12)

- Trigger: "Token" button (`btn-xs btn-outline-secondary`, new in Phase 6)
- Route: `assistant_chamber/print_token?queue_id={id}` — new controller method
- Behavior: Opens print view in new tab (`target="_blank"`)
- Print view shows: Hospital name, doctor name, patient name, serial number (large), date
- Format: Minimal HTML — 80mm thermal printer compatible (max-width: 300px, system monospace)

### bKash Initiate (PAY-01)

- Trigger: Select "bKash" method button → `#bkashSection_{qid}` reveals → click "Initiate bKash"
- AJAX POST to `payment_bd/bkash_initiate_desk` with `queue_id` and `amount`
- While in flight: button disabled, status text "Initiating..."
- Success response `{ success: true, payment_id: "..." }`: status text turns green "Initiated — {payment_id}"
- Failure response `{ success: false, message: "..." }`: status text turns red with message
- Network failure: status text "Request failed. Check connection." in red
- No page redirect — all state is inline in `#bkashStatus_{qid}`

### Record Fee (UI-13)

- Trigger: "Record fee" button (`btn-sm btn-primary`) in billing panel
- AJAX POST to `assistant_chamber/mark_queue_fee_paid_ajax`
- While in flight: button disabled + text "Saving..."
- Success: Toastr success "Fee recorded." + collapse billing panel
- Failure: Toastr error with message
- Network failure: Toastr error "Request failed. Please try again."

### Paid/Due Toggle (UI-13)

- Bootstrap `btn-group` with two buttons
- Click Paid: Paid button gets `.active`, Due loses `.active`, hidden input `pay_status = 'paid'`
- Click Due: Due button gets `.active`, Paid loses `.active`, hidden input `pay_status = 'due'`
- Default: Paid is active

### Cash / bKash Toggle (UI-13)

- Bootstrap `btn-group` with two buttons
- Click Cash: Cash active, bKash inactive, `#bkashSection_{qid}` hidden, `pay_method = 'cash'`
- Click bKash: bKash active, Cash inactive, `#bkashSection_{qid}` shown, `pay_method = 'bkash'`
- Default: Cash is active
